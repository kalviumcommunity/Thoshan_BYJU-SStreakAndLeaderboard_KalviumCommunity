# BYJU'S Streak & Leaderboard — API Documentation

This document provides a comprehensive API reference for the **BYJU'S Streak & Leaderboard Engine Backend**. All endpoints, request bodies, query parameters, response structures, and error states are documented directly from the implementation.

---

## 1. Overview & Base URL

- **Default Local Base URL:** `http://localhost:5000`
- **Docker / Production API Base Path:** `/api` (proxied via Nginx) or `http://localhost:5000`
- **Content-Type:** `application/json` for all request and response bodies (unless specified otherwise)

---

## 2. Authentication Flow

The backend implements a **Dual-Authentication Architecture** via the `verifyFirebaseToken` middleware (`backend/src/middlewares/auth.middleware.js`):

1. **Custom Application JWTs:**
   - Generated upon `POST /auth/register` or `POST /auth/login`.
   - Signed with `JWT_SECRET` (HMAC-SHA256) and expires in 7 days (`JWT_EXPIRES_IN`).
   - Token payload contains `{ id, email, name }`.

2. **Firebase ID Tokens:**
   - Generated by the frontend using Firebase Authentication (Google Sign-In / Firebase Email Auth).
   - Sent to `POST /auth/sync` to create or update the user in the PostgreSQL database.
   - Verified via the Firebase Admin SDK (`verifyIdToken`).

### Header Format

For all protected routes, include the Bearer token in the `Authorization` header:

```http
Authorization: Bearer <JWT_OR_FIREBASE_ID_TOKEN>
```

---

## 3. Standard Response Format

### Success Response Structure

```json
{
  "success": true,
  "message": "Optional descriptive message",
  "...": "Endpoint-specific payload data"
}
```

### Error Response Structure

All errors generated by controllers or captured by the centralized error middleware (`backend/src/middlewares/error.middleware.js`) return a standardized JSON structure:

```json
{
  "success": false,
  "message": "Error message describing the failure",
  "code": "OPTIONAL_ERROR_CODE"
}
```

### Common HTTP Status Codes

| Status Code | Description |
|---|---|
| `200 OK` | Request succeeded |
| `201 Created` | Resource successfully created |
| `400 Bad Request` | Invalid input or validation failed |
| `401 Unauthorized` | Missing, invalid, or expired authentication token |
| `403 Forbidden` | Access to resource forbidden |
| `404 Not Found` | Requested route or entity does not exist |
| `409 Conflict` | Unique constraint violation (e.g. email already registered) |
| `429 Too Many Requests` | Rate limit exceeded |
| `500 Internal Server Error` | Unexpected server failure |

---

## 4. Rate Limiting

The public authentication endpoints (`POST /auth/register` and `POST /auth/login`) are protected by an IP-based rate limiter (`express-rate-limit`):
- **Window:** 15 minutes (`15 * 60 * 1000` ms)
- **Max Requests:** 100 requests per IP per window
- **Exceeded Response (429):**
  ```json
  {
    "success": false,
    "message": "Too many authentication requests from this IP. Please try again after 15 minutes."
  }
  ```

### Authentication Endpoints

#### `POST /auth/register`

Register a new user account with email, password, and optional name. Hashes password using bcrypt (10 rounds) and returns a signed JWT.

- **Authentication:** Not required
- **Rate Limit:** 100 requests / 15 minutes per IP

##### Request Body
| Field | Type | Required | Description |
|---|---|---|---|
| `email` | String | Yes | Valid email address |
| `password` | String | Yes | Minimum 6 characters |
| `name` | String | No | User's display name |

##### Example Request
```bash
curl -X POST http://localhost:5000/auth/register \
  -H "Content-Type: application/json" \
  -d '{
    "email": "learner@byjus.com",
    "password": "SecurePassword123!",
    "name": "Aarav Sharma"
  }'
```

##### Success Response (`201 Created`)
```json
{
  "success": true,
  "message": "User registered successfully",
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "user": {
    "id": "c3e1b024-9b2f-48d6-848e-67011d8820c7",
    "firebaseUid": null,
    "email": "learner@byjus.com",
    "name": "Aarav Sharma",
    "createdAt": "2026-08-28T14:30:00.000Z",
    "updatedAt": "2026-08-28T14:30:00.000Z"
  }
}
```

##### Error Responses
- **`400 Bad Request`** (Invalid email or password under 6 chars):
  ```json
  {
    "success": false,
    "message": "Password must be at least 6 characters long"
  }
  ```
- **`409 Conflict`** (Email already exists):
  ```json
  {
    "success": false,
    "message": "An account with this email already exists"
  }
  ```

#### `POST /tasks/toggle`

Toggle or update the completion status of a specific task on a specific date.
- Enforces date-specific persistence using the unique constraint `(userId, taskId, date)`.
- Awards **15 points** and records an Activity on completion (`completed: true`).
- Reverts points and removes the Activity on uncompletion (`completed: false`).
- Recalculates streak in real-time.
- Duplicate completions on the same date return `pointsAwarded: 0` to prevent score inflation.

- **Authentication:** Required (`Bearer <token>`)

##### Request Body
| Field | Type | Required | Description |
|---|---|---|---|
| `taskId` | String | Yes | Task UUID |
| `date` | String | Yes | Target date formatted as `"YYYY-MM-DD"` |
| `completed` | Boolean | Yes | `true` for completed, `false` for incomplete |
| `timezone` | String | No | Client timezone (e.g. `"Asia/Kolkata"` or `"UTC"`) |

##### Example Request
```bash
curl -X POST http://localhost:5000/tasks/toggle \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "taskId": "e5f3d246-1d4a-60f8-060a-89233f0042e9",
    "date": "2026-08-28",
    "completed": true,
    "timezone": "Asia/Kolkata"
  }'
```

##### Success Response (`200 OK`)
```json
{
  "success": true,
```
